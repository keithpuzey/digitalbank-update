Key Findings & Recommendations

✅ Strengths

  • Live Streaming (HLS) Infrastructure — Excellent. All five HLS samplers (master playlist, audio/media playlists, audio/media segments) achieved sub-5ms average response times and error rates <0.002%, even at 192,000+ concurrent users simultaneously fetching ~350K HLS segment requests per second.
  • Homepage Performance — Outstanding. The landing page served 200,000 users with 0 errors. P99 latency of 428ms is well within acceptable thresholds.
  • CloudFront CDN Resilience. The CDN layer (d30aylox5wvifh.cloudfront.net) handled massive HLS media load (~11 TB transferred) with near-perfect reliability.
  • Scale Achieved. 192,204 peak concurrent virtual users — 96.1% of the 200,000 user target — were successfully ramped up and sustained for the test duration.

❌ Critical Issues

  • Authentication / Login Flow — Complete Failure at Scale.
    Click_LoginLink: 93.72% error rate (56,229 / 60,000 requests failed) with avg response time of 17.8 seconds and P90 of 30.5 seconds — indicating the login endpoint (rtmklik.rtm.gov.my/login) is completely overwhelmed. Errors are 503 (Service Unavailable) and 504 (Gateway Timeout).
    EnterUserDetails_ClickLogin: 84.37% error rate (50,621 / 60,000 requests failed) with avg response time of 45.8 seconds and P90 at timeout (60.3 seconds). These are 5-step transactions timing out.
  • Authentication backend capacity is the primary bottleneck. The login path fails catastrophically before the test even simulates full streaming load for authenticated users. This needs urgent attention before any live event.

⚠️ Warnings

  • Content API (rtm.glueapi.io) — HTTP 500 Errors. 7,193 errors (3.59%) on the streaming link click hit rtm.glueapi.io/v3/content/35272 with HTTP 500. This is the API that serves streaming content metadata. While the error rate is low, any content API failure prevents users from reaching the stream.
  • Peak VU Shortfall. The test targeted 200,000 VUs but reached 192,204 (a deficit of 7,796 users). This may indicate engine capacity limits and should be validated before production load events.
  • High Std Dev on ALL. The overall standard deviation of 628ms against a 11.6ms mean reflects the wide variance between HLS streaming (2-4ms) and the login flow (45,000ms). The HLS infrastructure is healthy; the login system is not.
Executive Verdict

The live streaming infrastructure (HLS via CloudFront) is production-ready at 200,000 concurrent users, demonstrating sub-5ms streaming response times and <0.002% error rates across 435+ million HLS requests and ~11 TB of data served.

However, the authentication and login system is a critical blocker. With 84–94% failure rates on login transactions, authenticated user flows will fail at scale. This must be resolved — through horizontal scaling of the auth backend, rate limiting tuning, session management optimization, or infrastructure upgrades — before any live broadcast event.

Additionally, the content API (rtm.glueapi.io) should be reviewed to resolve the 3.59% HTTP 500 rate on streaming link resolution.
